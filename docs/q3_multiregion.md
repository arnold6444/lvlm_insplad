# Q3 별도 9칸 복수 위치 평가 (v1)

사용자가 2026-10-20 승인한 별도 평가다. 기존 gold v2 및 133개 4지선다 문항과 결과를 보존한다. 원본 119개 수동 기록은 박스113/표시불가6이며 기존 seg20장을 합쳐 공간 정답133장을 확보했다. 이 gold는 이미 탐색된 자료이며 새 미사용 holdout이라고 주장하지 않는다. 방법 선택·튜닝은 dev에서 한다.

## 정답과 출력

원본 프레임을 같은 크기 3×3으로 나눈다. 번호는 위에서 아래, 왼쪽에서 오른쪽이다.

| 행 | 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|---|
| 위 | 1 | 2 | 3 |
| 중간 | 4 | 5 | 6 |
| 아래 | 7 | 8 | 9 |

각 결함 박스 중심이 속하는 칸을 **독립적으로** 구하고 중복을 제거한다. 두 박스가 1·9에 있으면 정답은 `[1,9]`이며, 두 중심을 평균내서 5로 바꾸지 않는다. 경계선에 정확히 있는 중심은 기존 coarse_region 함수처럼 가운데 행/열에 배정한다. 박스 하나가 여러 칸에 걸쳐도 중심 칸 하나를 대표 위치로 사용한다. 이는 박스 중심 위치 평가이며 픽셀 분할 또는 모든 물리 결함 개수 평가가 아니다.

- 정상107장: `regions_gt=[]`.
- 위치 정답이 있는 결함133장: `regions_gt=[...]`.
- 표시불가 결함6장: `regions_gt=null`, 결함 유무 평가에는 포함하고 위치 점수에서는 제외한다.
- 모델 출력: 정확한 JSON 객체 `{"regions":[1,9]}`. 결함 없음은 `{"regions":[]}`. 1~9 정수만 허용하고 중복, bool, 문자열, 미정의 키, 설명문은 invalid 처리한다. JSON 코드펜스 한 쌍만 허용한다.
- 모델은 정답 박스, GT 유형/유무, 파일명/경로, 다른 질문의 답을 보지 않는다. 원본/정상참조 이미지와 고정 프롬프트만 본다. Q1/Q2는 호출하거나 바꾸지 않는다.

## 점수

- 결함 유무: 전체246장의 TP/FP/TN/FN, recall/specificity/BAcc, invalid 개수. Invalid 정상은 FP, invalid 결함은 FN으로 별도 표시한다. 표시불가6장도 포함한다.
- 위치: 알려진 결함133장의 **전체 정답집합 정확도**, 공간 정답이 알려진 전체240장의 맞춘 칸 TP·놓친 칸 FN·잘못 지목한 칸 FP 및 micro precision/recall/F1. 정상의 잘못 찍은 칸도 FP에 포함한다. Invalid는 정답집합 실패와 GT칸 전부 미탐으로 계산하고 invalid를 별도 보고한다. Invalid의 허구 위치 FP를 임의로 만들지 않는다.
- 정상107장의 잘못 지목한 칸 수를 별도로 보고한다. 정상/결함을 합친 집합 정확도도 보조로 보고하지만 주지표는 결함133장이다.
- `null` 공간 정답은 점수 분모에 넣지 않는다. 한 클래스만 있는 그룹의 BAcc 및 분모0의 precision/F1은 null이다.
- 전체뿐 아니라 자산·결함·라벨 출처별 support와 점수를 저장한다. 항상없음/항상중앙/항상9칸 대조군도 함께 저장한다.

## 비교와 실행

- direct: 모든 이미지에서 한 번에 여러 결함 위치를 묻는다.
- staged: 유무를 먼저 `{"present":true|false}`로 묻고 true일 때만 위치를 다시 묻는다. 위치 단계는 독립적으로 재확인하며 []도 허용한다. invalid 유무는 invalid 최종 출력이지 정상으로 대체하지 않는다.
- 두 방식의 실제 호출 수를 저장한다. 이 비교만으로 검증 구조의 인과 효과를 주장할 수 없다. 동일 호출 예산 대조군은 추후 별도 dev 실험이다.
- HF InternVL 기존 native adapter/greedy/80-token/max_total_tiles6를 사용한다. 같은 조건에서는 `[reference,target]` 순서를 고정한다. 기본 참조는 master QA의 같은 자산 train-normal 고정 참조이며 retrieved-diffdate라고 부르지 않는다.
- 모델은 고정 revision의 local snapshot을 사용한다. 실제 실행은 VRAM20GB 이상에서만 허용한다. 로컬 CPU 검증은 주입 fixture로만 수행한다.
- 데이터·원본 이미지·코드·프롬프트·모델 revision·조건을 input lock으로 묶고 변경되면 기존 출력 폴더 재사용을 차단한다. 각 호출 직후 원문/시간/오류를 저장하고 20호출마다 진행을 출력한다. 오류 호출만 재실행하며 invalid 응답은 그대로 보존한다.
- 완료 결과만 ZIP으로 내보낸다. GitHub 자동 게시/Drive 업로드/추론 자동 실행은 없다. Colab은 `RUN_INFERENCE=False` 기본값이다.

## 육안검토 결과와 남은 한계

- 검토한 원본18장의 SHA256이 기존 gold 입력 manifest와 일치했다.
- 수동 복수 박스12장 중 누락10장은 분리된 빈 애자 자리를 각각 표시하는 구조와 맞는다. rust2장은 넓게 퍼진 표면 변화의 대표 영역으로 보이며 완전한 영역 포괄은 전문가 확인 전이다.
- 제외6장은 전체 부품은 보이나 표면 변화가 넓거나 재질/코팅과 부식의 경계가 불명확하다. 이번 검토만으로 제외를 확정/취소하거나 정상으로 바꾸지 않는다. 기존 제외 상태를 보존한다.
- v1은 새 수동 정답을 추가하지 않는다. 다른 칸에 걸친 넓은 결함의 정확한 extent는 별도 segmentation 정답 없이 주장하지 않는다.
- 추가 검토 대상은 `core-1649058f31adda54`(01-06-2021_DJI_0335_100.jpg), `core-2e7ae5a3c54051f2`(01-06-2021_DJI_0547_159.jpg)다. 첫 사진은 큰 박스 안 배경과 위쪽 부식 후보, 둘째는 박스 밖 오른쪽/아래 표면 변화의 포함 여부를 전문가가 확인해야 한다. 코드가 임의로 추가·삭제하거나 정답으로 확정하지 않는다.
