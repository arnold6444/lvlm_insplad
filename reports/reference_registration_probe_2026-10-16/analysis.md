# 정상 참고사진 정렬 가능성 — 2026-10-16

**고정 SIFT/호모그래피 방식은 실제 8쌍 모두 최소 정렬 기준을 통과하지 못했다. 합성 대조군은 양성7/7·음성7/7을 통과했고 알고리즘 오류는0이다. 이 설정으로 차이영상이나 부품 대응 근거를 만들어 LVLM에 전달하지 않는다.**

## 고정한 질문과 방법

답변만 재검토하는 Q2 방식은 누락 정답을 늘리지 못했고, 독립 공개 검출기도 최소 부품 후보 기준을 실패했다. 이번에는 같은 검사 대상의 기존 정상 참고사진을 실제로 맞출 수 있는지를 선행 검사했다. 기존 검색/자동 타일 확대/답 재질문과 달리 이미지 사이의 점 대응과 기하 변환을 직접 검사한다. 기존 코드에 이 정렬 실험이 없음을 확인한 뒤, 결과를 보기 전 docs/reference_registration_probe.md에 가설·대조군·기준·중단 조건을 고정했다.

[OpenCV 공식 설명](https://docs.opencv.org/4.13.0/d1/de0/tutorial_py_feature_homography.html)의 SIFT 대응점·ratio test·RANSAC 호모그래피 절차를 사용했다. 같은 평면/호환되는 시점과 충분한 대응점이 필요하다는 방법상의 제한이 있다. 문서가 InsPLAD에서의 성공을 보장하는 것은 아니다.

기존 design40 유리 애자8개와 고정된 고유 정상 ref7개, 합계15개 이미지를 그대로 썼다. 과거 detector 점수나 QA 정답으로 쌍을 고르지 않았다. 검사8쌍, 정상7장의 고정 변환 양성7건, 8×8타일 재배열 음성7건 =22건. Q1/Q2/Q3 답·gold·결함 GT는 알고리즘 입력에 없다. 원본 member 경로에 포함된 class 문자열을 읽어 추론/필터링/변환에 사용하지 않았다.

실제 실행은 **기존 Dot 클라우드 브라우저 안 Colab의 CPU**, OpenCV4.14.0. 모델/GPU/LVLM/학습 호출0. 정상참고 중복은 대조군에서 한 번만 처리했다. longest side1024, SIFT4000, 양방향 ratio.7, RANSAC3px/seed42, 최소 inlier12·비율.5·양쪽 convex-hull 면적비.15·중앙 양방향 오차3px 이하. 양성은 알려진 변환의 내부4×4격자 복원 오차3px 이하도 요구했다. 양성·음성 각각6/7, 실제6/8을 모두 만족해야 최소 가능성 통과다. 임계값 선택이나 재시도는 하지 않았다.

## 결과와 독립 검산

| 항목 | 결과 | 사전 기준 |
|---|---:|---:|
| 알려진 변환의 정상 사진 복원 |7/7|6/7 이상|
| 타일을 뒤섞은 사진 거부 |7/7|6/7 이상|
| 실제 정상 ref→target 정렬 |0/8|6/8 이상|
| 알고리즘 오류 |0|0|

양성의 내부 격자 복원 중앙 오차는 .011~.138px다. 실제8쌍의 양방향 ratio 대응점 수는 0/1/0/1/5/0/0/3개에 불과했고, 모든 실제 쌍에서 유효 H를 얻지 못했다. 대응점을 안정적으로 확보하지 못한 실패이며, 실제 공간 정확도는 GT가 없어 null이다. 합성 음성 거부율은 이 인위적 타일 파괴에 관한 진단이지 자연 사진의 오정렬률 추정이 아니다.

정성 관찰상 일부 검사/ref는 애자 배열 수·배경·촬영각이 크게 다르고, 일부는 외형이 가까워도 국소 대응점이 부족했다. 이것이 유일한 원인이라고 확정하지 않는다. 같은 자산 범주의 정상 예시가 픽셀 단위로 정렬 가능한 동일 물체/동일 부위 사진이라는 보장은 없음을 이 작은 고정 설정에서 관찰했다. 모든 정렬 기법이나 참조 검색이 무효라는 결론은 아니다.

소스·manifest·노트북 내 포함 소스, 원본15이미지 SHA, raw22건의 대응점/마스크/H/양방향 오차/독립 convex-hull 면적/알려진 변환·격자 오차·요약 gate를 감사했다. 반복 추론이나 정렬 재계산 없이 저장된 raw 수치를 검산했다. 감사 스크립트는 runner를 import하지 않는다.

- source ZIP SHA256 `9b7ee9ba5bd0e004fcc4f4447b26db0d3b352ffd8a14d0764407b902d7c57782`
- result ZIP SHA256 `77d9715f0292e6001b49cbc8b658e1d9579dfecb6549fee0b00de7834a36d67c`, 원격·회수 사본 일치
- 등록 연산 latency 합23.537초. 이미지 ZIP 읽기·명령 전달·인증·다운로드를 포함한 왕복 시간이 아니다.
- 첫 긴 bootstrap 명령과 이후 hash 명령은 원격 초점 전환 직후 앞부분이 누락돼 셸 단계에서 실패했다. 화면에서 과학 연산이 시작되지 않았음을 확인했고, 초점이 잡힌 뒤 짧은 명령으로 해시 확인→압축해제→launch 단일 실행했다. 실제22건은 called22/reused0, 중복 계산0.
- `complete:true`는 연산 종료이며 최소 가능성 성공이 아니다. source/input/config identity가 바뀌면 재사용을 거부한다.

## 판단과 재현

이 고정 설정은 확대·튜닝·다른 seed·잔차 기반 결함 판정·LVLM 결합으로 이어가지 않는다. Q1과 QA 결과는 전혀 변경되지 않았고 QA 효과는 측정하지 않았다. 후속 고성능 정렬 모델의 성공 가능성은 미검증이다.

자체 소스와 입력 manifest를 포함한 `notebooks/lvlm_reference_registration_probe_colab.ipynb`, 실행기 `scripts/run_reference_registration_probe.py`, protocol `docs/reference_registration_probe.md`를 보존했다. 로컬 `tests/test_reference_registration_probe.py` 3개는 합성 coordinator fixture, 실제 OpenCV의 변환 복원 검증은 이번 Dot Colab 대조군7건이다. 두 검증을 혼동하지 않는다. `audit_probe.py`는 결과 ZIP을 재집계하며, 원본 QA/결과/gold에는 쓰지 않는다.
