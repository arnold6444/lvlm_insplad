# Q3 누락 정답 crop 진단 코랩 준비

사용자가 완료한25개 실제 표시(박스24/판단불가1)를 고정하고, 기존 후보 확대 경로와 겹치는 위치 정답20장을 세 조건으로 비교하는 독립 코랩을 만들었다. **기능 제작·CPU 검증과 실제 모델 효과는 별개이며, 실제 GPU 실험은 아직 실행하지 않았다.**

실행 파일: `notebooks/lvlm_q3_gt_crop_diagnostic_dev_colab.ipynb`. L4/A100에서 기본값으로 모두 실행하면 `q3_gt_crop_diagnostic_dev20_results.zip`을 저장한다. 표시 자료와 기존 후보는 내장했으며 원본 데이터 ZIP 두 개만 Drive에서 자동 검색한다.

## 고정 조건

- 기존 후보 칸 / 사람 정답 칸 / 사람 정답 박스(+각 방향25% 여백), 각각 새 질문1회, 최대60회 LVLM. 정상 참조+원본+확대판, 타일3/3/2,greedy80토큰, 기존 pinned native InternVL, 양자화 없음.
- 질문은 세 조건에서 완전히 같다. 확대판은1024×548의 두 슬롯이며 미사용 슬롯은 흰색이다. 정답 칸 번호·박스 좌표·oracle 이름·결함 있다는 주장을 질문/이미지 설명에 넣지 않는다. 정답은 crop 픽셀 선택에만 쓰며 원본9칸 답을 평가한다.
- 실제 표시 SHA `9a9e71b995174288e3507e0d60f97fd155abb2149de2bf4ee0feb10fe02d52d3`; 기존 실제 PR64 ZIP SHA `dc60885b0e8a98cd2bc30804385d7bb3dc0b33445059e9ed1b847e41171268d4`.
- 판단불가1/기존후보보류1/기존경로밖3을 제외한 같은20장. 기존 dev이며 새로운 holdout이 아니다. 정상 지원0이므로 정상 FPR/특이도/균형정확도는 미평가다.
- 정답 조건은 진단용이며 실제 Agent 점수가 아니다. 후보vs정답칸은 위치 선택을, 정답칸vs정답박스는 크기·주변 문맥을 진단한다. 두 조건이 성공해도 정상 오탐·실제 위치 도구·별도 최종 평가는 여전히 필요하다.

## 실제 수행한 검증

- 관련 테스트57개: 새 진단25개+기존 가림14개+표시18개. GT/원본 SHA/좌표/범위/경계/다중 부위/정상 참조/고정 dev 검증,무효 오답 유지,오류만 재시도와 이력,중단 재개,요청·crop·코드·입력 조작 거부.
- 코랩 내장 소스31개 해시와 코드4셀 컴파일 확인. 내장된 정확한 runner로 원본20장과 같은 정상 참조를 검증하고, **모델 대신 항상 빈 JSON을 반환하는 fixture60회**로 입력/저장 연결만 확인했다. 이것은 모델 결과가 아니다.
- 확대판60개/실제 부위84개의 좌표·확대 픽셀을 원본에서 별도로 재구성해 대조했다. 모든 조건에서 질문1종류·동일 확대판 크기·타일예산 확인. 재개 시 fixture추가 호출0/모델 로드0.
- 최종 ZIP 저장 셀도 로컬 가짜 다운로드 콜백으로 실행했다. raw60개·소스 capsule 보존, 원본 사진 제외,fixture표시 유지 확인. 실제 Drive/GPU 연결을 재실행한 검증은 아니다.
- 내장 소스를 별도 경로에서 추출해 새 진단 테스트25개를 추가 실행해 통과했다. 최종 통과 결과는 `verification.json`에 기록한다.

## 보존과 남은 일
