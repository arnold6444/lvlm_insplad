# 최신 결과 정리 (2026-10-23 기준)

기존 [`README.md`](README.md)의 표 1~5는 2026-10-08 gold v2 단일 질문(MMAD 방식) 비교다. 이 문서는 그 뒤에 나온 **검증 agent 결과와 후속 실험**을 한곳에 모은다. 모든 수치는 실제 Colab 실행 결과를 로컬에서 독립 검산한 값이다. 대부분의 원본 보고서는 `reports/` 아래 로컬 폴더에만 있다. 호출 수 대조 실험은 결과(`results/latest/gold_v2_matched_call/`)와 감사 보고서(`reports/gold_matched_call_evaluation_2026-10-23/`)를 GitHub에 올렸다. 논문 초안은 [`reports/paper_draft_2026-10-23/`](../paper_draft_2026-10-23/README.md)에 있다.

## 한 줄 결론

정상 참조와 단계적 검증을 쓰는 LVLM 검사 구조는 **전체 분류 성능과 정상 오경보를 개선**하지만, **부품 누락과 결함 미탐은 오히려 나빠진다.** 이 개선은 **같은 호출 수로 다시 묻기만 해서는 재현되지 않으므로 구조(정의·단계형 Q3)의 효과다**(표 A-3). 확대·문구 변경·다른 모델·이상탐지 모델을 추가해도 일관된 추가 개선은 없었다.

**범위 동결 (2026-10-23)**: 부품 누락 분기는 종료했다. 남은 실험은 없고, 이제 논문을 정리한다.

## 주장할 수 있는 것 / 없는 것

| 주장 가능 | 주장 불가 |
|---|---|
| 검증 구조가 직접 질문보다 Q2 F1·Q3 유무 정확도를 개선 (CI가 0 제외) | 수정 후보가 기존 agent보다 낫다 |
| 그 개선은 호출 수를 맞춘 다시 묻기로는 재현되지 않는다, 즉 구조의 효과다 (CI가 0 제외) | 정의와 단계 분리 중 어느 쪽이 얼마나 기여했는지 (따로 빼 보지 않음) |
| 정상 오경보 감소와 결함 미탐 증가가 동시에 일어남 | Q3에서 결함 위치를 정확히 찾았다 (위치 정답 없음) |
| 부품 누락은 검증을 추가할수록 더 놓침 | 다른 모델·다른 자산으로 일반화된다 (InternVL 중심, 누락은 유리 애자만) |
| 확대·문구·모델 교체·이상탐지 모델은 일관된 추가 개선이 없음 | gold가 완전히 새로운 미사용 시험 세트다 (과거 탐색 이력 있음) |
| 다시 묻기 자체가 답을 "정상" 쪽으로 쏠리게 한다 (표 A-3) | "보수적으로 변한" 정확한 내부 원인 (현상과 대조 결과만 확인) |
| 부품 누락은 정답 위치 crop을 줘도 LVLM이 인식하지 못한다 (0/20) | |

## 다음 단계 (2026-10-23 범위 동결 후)

1. ~~구성요소 제거 비교 (호출 수 맞춤)~~ → **완료**(표 A-3, 구조 효과 확인). 정의와 단계를 하나씩 빼는 세부 비교는 하지 않는다.
